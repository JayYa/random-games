# 是但

是但帮你做随机决定。你挑一个主题，比如「今天吃什么」，站点替你抽一种玩法。你玩一次，站点从这个主题的名单里摇出一个中选。

线上地址：<https://jayya.github.io/random-games/>

名单是仓库里的 CSV 文件，没有后端，也没有数据库。改名单和加主题都只动 `public/` 下的文件，不动代码。

## 玩一次

1. **选主题。** 在首页挑这一次要决定的事。
2. **等站点抽玩法。** 站点从转盘、弹球机和求签筒里随机定一种。你挑不了，也不能在玩法页里换。上一次抽出的玩法，这一次不会再出。
3. **开抽。** 每种玩法的操作见下表。
4. **看揭晓。** 盘面停下后，站点抽出中选，把名字亮在停下的那一格上，再弹出结果卡片。在结果卡片上收下中选，名字就从盘面抹掉，可以再开抽一次。

| 玩法 | 盘面 | 操作 | 名字亮在 |
| --- | --- | --- | --- |
| 转盘 | 12 个等分的扇区，顶部一个指针 | 按「转」 | 指针所指的扇区 |
| 弹球机 | 钉阵、风车、弹力柱，底部 8 个落格 | 拉下柱塞再松手 | 球落进的落格 |
| 求签筒 | 一只竹筒，插着 9 根空白的签 | 拖着签筒左右甩，或者摇手机 | 掉出筒口的那根签 |

在有些手机上，要先点「开启摇手机」授权，才能摇手机甩签筒。

### 盘面不决定谁中选

盘面是匿名的。开抽之前，盘面上没有候选的名字，也看不出名单里有几个候选。盘面停下之后，站点才从启用且不在冷却中的候选里等概率抽出中选。停在哪一格，不影响谁中选。

同一主题最近 7 次的中选是这个主题的最近中选，它们在冷却中，这一次抽不到。启用的候选不多于 7 个时，站点只冷却最新的「候选数 − 1」个，所以总有一个候选抽得到。

最近中选和最近玩法只存在这台浏览器里，页面上不显示。要重置它们，清掉这个站点的浏览器数据。

## 改名单

每个主题有一份名单文件，都在 [public/](public/) 下。名单文件每行一个候选，两列 `name,enabled`，没有表头行：

```csv
# 以 # 开头的行是注释，空行会被跳过
沙县小吃,true
"老王烧烤, 二店",true
再也不去的那家,false
```

- `name` 是候选的名字。名字里有逗号时，用双引号把整个名字包起来。名字里要写双引号时，把它双写成 `""`。
- `enabled` 写 `false`、`0` 或 `no` 时，这个候选停用，不区分大小写。停用的候选留在文件里，但永远不会中选。其余写法都算启用，包括留空和整列缺失。

要改线上的名单，在 GitHub 网页上编辑名单文件，提交到 `master`。推送后，GitHub Actions 先跑测试，再重新构建并部署。测试不过时，线上保持原来的版本。

名单开不了抽时，玩法页不出盘面，改为说明哪里坏了、怎么改。开不了抽的原因有四种：文件没取到、文件读不懂、文件是空的、候选全部停用。

## 加一个主题

往 `public/` 放一份 CSV，头部写一行 `# entry:`，站点上就多一个主题，不用改代码。下面这份文件存成 `public/drink.csv`，就是一个完整的主题：

```csv
# entry: 今天喝什么
瑞幸,true
星巴克,true
```

### 在注释行里写主题的说法

名单文件的注释行里可以写两个键。键后面紧跟半角冒号，构建时裁掉冒号后面的首尾空白。

| 键 | 用在哪 | 必填 | 没写时 |
| --- | --- | --- | --- |
| `entry` | 选主题页上这个主题的入口 | 是 | 构建跳过整份文件 |
| `title` | 玩法页上的大标题 | 否 | 用 `entry` 的值 |

`entry` 必填，因为 `drink` 这样的文件名没法当成选主题页上的说法。两个键都写的文件是这样的：

```csv
# entry: 今天喝什么
# title: 今天喝哪杯

瑞幸,true
星巴克,true
```

只有这两个键有特殊含义。其余 `#` 行都当说明文字跳过，所以名单头部写给人看的说明不会当成配置。

### 用文件名定地址

文件名决定主题的地址：`drink.csv` 的地址是 `#/drink`。打开这个地址后，站点抽出玩法，地址变成 `#/drink/wheel` 这样的形式。所以写文件名的时候，你就知道发给别人的链接长什么样。

文件主名只能用小写字母、数字和连字符，也就是 `[a-z0-9-]+`。大写字母、中文和空格都不行，否则地址栏里会出现一串百分号转义。

### 写坏的文件只影响它自己

文件名不合规，或者漏了 `# entry:` 这一行时，构建跳过这份文件并打一行日志。本地跑 `pnpm dev` 时也打这行日志。构建照常成功，其余主题照常上线。

因为被跳过的文件不会让构建失败，所以要靠测试发现它。`pnpm test` 里有一条测试遍历 `public/*.csv`，断言没有一份文件被跳过。另一条测试断言每份名单都能开抽。

构建时扫描 `public/*.csv` 得出主题清单，并编译进产物，所以浏览器不会为此多发一次请求。要知道站上有哪些主题，看 `public/` 下有哪些 CSV。

## 在本地跑起来

```bash
pnpm install
pnpm dev        # 开发服务器
pnpm lint       # oxlint
pnpm test       # vitest 单元测试
pnpm build      # tsc --noEmit，再 vite build
pnpm test:e2e   # Playwright 冒烟测试，自己先构建再起 vite preview
```

站点用 TypeScript 和 Vite 写，不用前端框架。弹球机的物理用 [matter.js](https://brm.io/matter-js/)，它是仓库唯一的运行时依赖。

每个 PR 上，[CI](.github/workflows/ci.yml) 跑 lint、单元测试、构建和冒烟测试。推送到 `master` 后，[部署工作流](.github/workflows/deploy.yml) 跑单元测试，构建站点，再发布到 GitHub Pages。
