# 弹球机的中选由物理仲裁

转盘先决定结果再反算旋转角度（[ADR-0003](./0003-result-first-animation-second.md)）。弹球机反过来：中选由球实际落进哪个落格决定，没有人预先选好它。这是刻意的分歧，不是遗漏。

理由是弹球机的存在意义就是让用户对结果有参与感——力度和发射时机是用户真实握在手里的两个变量。ADR-0003 拒绝甩动手势，正是因为在"结果先定"的前提下，力度会**假装**能影响结果；弹球机把前提换掉，于是力度可以真的影响结果。两条 ADR 因此不冲突：它们是同一条原则（用户能操作的东西必须真的算数）在两种不同前提下的结论。

## Consequences

- **这个玩法明确不公平**，用户可以练出手感、偏好某几个落格。这是特性不是缺陷，不要"修"它。钉阵和弹力柱负责把力度差异打散，让它不至于变成纯技巧游戏，但目标从来不是等概率。
- **物理必须是确定性的**：定步长积分，`(力度, 风车相位, 种子) → { 落格, 轨迹 }` 是一个纯函数，进单元测试。随机性来自种子对开局的微扰，不来自浮点漂移。
- **先跑完模拟，再回放轨迹**。发射的瞬间把整段模拟跑完（几毫秒），拿到落格和完整轨迹，再按帧播放。这样"物理仲裁结果"和"结果在动画前已确定"同时成立——仲裁者是物理，只是物理跑得比动画快。回放按累积时间索引轨迹并对球心做线性插值，因此高刷屏和掉帧都不改变球的速度。
- **模拟卡住有兜底，且用户看不见**：球卡在两颗钉之间或贴墙无限微弹时，模拟超过步数上限就换一个种子重跑；重试用尽才落到"判给当前横坐标最近的落格"。因为模拟发生在回放之前，用户永远看不到卡住的球。
- **落格判定是"进格即定"**：球心越过隔板顶部所在的水平线那一帧即判定，之后的弹跳只是余韵。备选的"停稳才定"会出现"进了 3 号格又跳到 4 号格"，观感上像作弊；判定规则必须一句话说得清，且和肉眼所见的那一刻一致。
- **风车在发射前就在转**，相位对用户可见，在按下发射的瞬间快照后喂进模拟。若改成发射后才启动，风车就退化成一个隐藏的随机数发生器，不如不做。
- **弹球机是这个站第一个键盘不可达的页面**（其余每一页的按钮和返回入口都刻意做成了键盘可达）。柱塞是拖拽 + 挑时机的指针交互，暂不提供键盘等价操作。这是明知代价的取舍，不是疏忽。
