# 名单存为仓库内的 CSV，不做后端

名单几个月才改一次，不值得引入数据库和 API。每个主题的名单是 `public/` 下的一份 CSV，提交进仓库，进入玩法页时运行时 `fetch`；改名单就是改文件并推送（GitHub 网页上直接编辑也行）。站点因此是纯静态的，由 Actions 构建、部署在 GitHub Pages。

## Considered Options

- **浏览器内编辑 + localStorage**：名单变成每个浏览器各一份，失去"一份共享名单"的意义。
- **真后端 + 数据库**：能多人在线改，但为一个几十行、几个月改一次的列表付出运维成本不成比例。

## Consequences

- 选运行时 `fetch` 而不是构建期打进 bundle，是为了保住"CSV 是一份独立的数据文件"。代价是页面要处理加载中和加载失败。
- CSV 写坏只能在运行时发现，所以解析错误必须显示在页面上并指明行号，不能只进 console。
