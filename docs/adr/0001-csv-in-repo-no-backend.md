# 名单存为仓库内的 CSV，不做后端

改名单的频率大约是几个月一次，为此引入数据库和 API 不划算。名单是 `public/restaurants.csv`，提交进仓库，网页在运行时 `fetch` 读取；改名单等于改文件并推送（也可以直接在 GitHub 网页上编辑该文件）。站点因此是纯静态的，部署在 GitHub Pages 上，由 Actions 构建。

## Considered Options

- **浏览器内编辑 + localStorage**：零后端，但名单会变成每个浏览器各自一份，失去"一份共享名单"的意义。
- **真后端 + 数据库**：多人可在线增删改，但为一个每几个月改一次的几十行列表付出的运维成本不成比例。

## Consequences

选择运行时 `fetch` 而非构建期把 CSV 打进 bundle，是为了保住"CSV 是一份独立的数据文件"这个语义。代价是页面必须处理加载中和加载失败两种状态；并且 CSV 的格式错误只能在运行时发现，所以解析错误必须显示在页面上并指明行号，不能只写进 console——否则改坏了 CSV 只会看到一个空转盘。
