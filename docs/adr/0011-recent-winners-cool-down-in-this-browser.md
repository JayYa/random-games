# 最近的中选和玩法在这台浏览器里冷却

纯等概率抽取会让昨天和今天抽出同一个候选，连着几天撞上就很烦。因此每个主题在浏览器里记下**最近中选**（最近 7 次），它们**冷却**、不参与下一次抽取；抽玩法同理，记下**最近玩法**（最近 1 次），上一次抽出的玩法这一次不会再出。两边是同一套规则，只是次数不同：玩法种类少，冷却多了就只剩固定顺序轮流。

记忆存在浏览器的 localStorage 里：站点没有后端（[ADR-0001](./0001-csv-in-repo-no-backend.md)），这是唯一不引入服务器的地方。

## Considered Options

- **往 CSV 加权重列**：只能压低某个候选的整体频率，治不了"刚抽过又抽到"。
- **按时间窗口冷却（最近 X 天）**：隔一阵子没开就会全部解冷或全部还冷着，不如按次数好推理。
- **降权而非排除**：最近抽过的仍有机会再中，"不能一样"就做不到。
- **只记用户最终采纳的那个**：站点不知道用户采纳了哪个；被"再抽一次"甩掉的候选本来就是最近不想要的。

## Consequences

- **中选不再在全部启用的候选里等概率**，只在启用且不在冷却中的候选里等概率。盘面仍是匿名的，冷却对用户不可见，页面不显示历史、不给清空按钮。
- **记忆各浏览器一份**：手机和电脑各记各的，无痕模式或清掉浏览器数据就从头来。存储不可用或读出坏数据时，静默退化为没有记忆的等概率抽取。
- **可抽的永远至少一个**：冷却个数取 `min(N, 可抽总数 − 1)`，最早的先解冷。只有两种玩法时，抽玩法就是转盘与弹球机轮流。
- **每一次中选都记**，在盘面停下、名字亮出的那一刻就记，不等用户收下卡片——否则关页重开就能反复刷出同一个。最近中选按名字记，名单里改名、删除或停用的名字照旧占一格，几次之后自然被挤出去。
- **最近中选按主题分，最近玩法全站一份**。只有真正抽出来的玩法才进最近玩法；直接打开带玩法的地址（书签、别人发的链接）不算。
- **站点仍不记住上次选的主题**（[ADR-0005](./0005-one-csv-per-theme.md)）：记中选是为了抽得好，记主题则是替人做选择。
