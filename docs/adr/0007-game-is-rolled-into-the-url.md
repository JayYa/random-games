# 玩法是随机抽的，抽完写进地址

选完主题后，站点随机抽一种玩法（冷却见 [ADR-0011](./0011-recent-winners-cool-down-in-this-browser.md)），不让用户挑：随机是这个站的主张，连"用什么方式随机"也随机，还省掉一个用户不在乎的决定。地址是 `#/<主题>/<玩法>`；`#/<主题>` 是稳定入口，进来先抽玩法，再 `replaceState` 成带玩法的地址。直接打开带玩法的地址（书签、链接）不抽，就玩那个。

## Consequences

- **玩法地位对等**，没有默认玩法独占 `#/<主题>`：否则每加一个玩法都要重问"它算不算默认"，收藏入口的人也会以为收藏的是那个玩法。
- **用 `replaceState` 不用 `pushState`**：后退键从玩法页直接回首页，而不是变成"再抽一次玩法"的按钮。认不出的地址回落首页时同样替换成 `#/`。
- **页头的「换个主题」是后退，不是前往**：从首页点进来的就后退一步；从链接、书签直接落进来的，后退会出站，改成原地换成首页。"上一页是不是首页"记在这条历史的 `history.state` 上，刷新不丢。入口仍是真链接，中键和带修饰键的点击照链接办。
- **玩法页内不能换玩法**：给出换的入口，等于把挑玩法交还给用户。想换就回首页重进。
- **不向用户解释玩法是抽的**，也没有"正在抽玩法…"的过场。
- **加一个玩法 = 往玩法清单里加一条记录**，玩法只交盘面（[ADR-0012](./0012-games-only-supply-a-board.md)）。
