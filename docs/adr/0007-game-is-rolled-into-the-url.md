# 玩法是随机抽的，抽完写进地址

选完主题后，站点随机抽一种玩法（转盘或弹球机，50/50），而不是让用户挑。随机本身就是这个站的主张——连"用什么方式随机"也随机，比多给一个选择更贴题，也省掉了一个用户根本不在乎的决定。

地址结构是 `#/<主题>/<玩法>`，例如 `#/eat/pinball`。`#/eat` 保留为稳定入口，语义从"吃的转盘页"变成"帮我决定今天吃哪家"：进入它就抽一次玩法，然后 `replaceState` 换成带玩法的地址。直接打开带玩法的地址（书签、别人发的链接）不抽签，就玩那个玩法。

## Consequences

- **两种玩法地位对等**，转盘的规范地址是 `#/eat/wheel`。让转盘继续独占 `#/eat` 会省一次跳转，但每加一个玩法都要重问一次"它算不算默认"，而且收藏 `#/eat` 的人会以为自己收藏了转盘。
- **用 `replaceState` 不用 `pushState`**：后退键从玩法页直接回首页。若把 `#/eat` 留在历史里，后退键就变成了一个"再抽一次玩法"的按钮，会有人反复按。
- **玩法页内不能换玩法**，不提供"换个玩法"入口。理由同 [ADR-0002](./0002-lineup-has-a-per-game-cap.md) 里"不能在用户开摇之后偷换盘面"：中途换玩法比中途换候选更过分。想换就回首页重进，这条路径本来就在页头的返回链接上。
- **不向用户解释玩法是抽的**，首页和玩法页都不加说明文案，也不做"正在抽玩法…"的过场动画。过场在每次进页面时插一段等待，很快就烦。
- **加第三个玩法 = 往玩法注册表里加一条记录**，与主题清单（[ADR-0005](./0005-one-csv-per-theme.md)）同构：一条记录带 slug、名字、上盘名单上限和挂载函数，路由层只认这个接口。取 CSV、加载态、错误页、页头、结果卡片与撒花都属于路由层共享，不属于任何一个玩法。
