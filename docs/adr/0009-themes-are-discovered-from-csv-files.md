# 主题由 `public/*.csv` 在构建期自动发现

加一个主题曾经是两步：写一份 CSV，再往 `src/themes.ts` 的 `THEMES` 里加一条记录。这两步之间的重复注定要漂移，而第二步把加主题变成了一件要动代码的事。现在改成一步：**主题就是 `public/` 下的一份 CSV**，它的四条文案写在文件头部的注释里，构建期扫出来生成清单。

这条 amends [ADR-0005](./0005-one-csv-per-theme.md)，不推翻它。0005 的结论——一个主题恰好一份 CSV、hash 路由、错误提示一律中性、首页不读任何名单——全部继续有效；被改掉的只有"清单是 `src/themes.ts` 里的常量表"这一句。

0005 当年否决过"主题清单也做成数据"，理由是给站点添了新的运行时失败模式：清单取不到、写坏了，首页连按钮都渲染不出来。这个担忧仍然成立，所以发现只发生在**构建期**——生成的是一个编译进 bundle 的虚拟模块，浏览器里没有多出任何一次请求，也没有多出任何一种失败。被推翻的不是那条理由，是"因此清单只能手写"这个结论。

## 文案写在 CSV 头部

三个键，半角冒号，写在 CSV 的注释行里：`# entry:`（首页入口的说法）、`# title:`（玩法页大标题）、`# result:`（结果卡片上那句话）。键是封闭的白名单，其余 `#` 行照旧当散文跳过——现有 CSV 头部那段说明文字里不存在这种写法，不会误伤。

`entry` 必填：首页入口是唯一没法从文件名猜出来的东西，总不能在首页上写个 `drink`。`title` 和 `result` 选填，缺了退回中性说法。slug 就是文件主名，只接受 `[a-z0-9-]+`——宁可跳过一份文件，也不要地址栏里出现 `%E6%88%91%E7%9A%84`。

## 坏文件跳过，不拦构建

文件名不合规或缺 `entry` 的 CSV 被跳过，`console.warn` 一行说明是哪个文件、为什么跳过，构建照常成功。数据文件是给非程序员改的，一份写坏的名单不该让整个站点发不出去。

代价是坏文件会静默地不上线，而 CI 日志没人翻。**拦它的是测试而不是构建**：一条冒烟测试遍历 `public/*.csv`，断言每一份都能解析成主题。`pnpm test` 跑在 `pnpm build` 之前，所以写坏的文件仍然拦得住、拦在部署之前，只是构建本身永远不会因为数据而崩。

## Consequences

- 加第四个主题 = 往 `public/` 扔一份带 `# entry:` 的 CSV。不动代码，不改测试。
- `THEMES` 不再是源码里读得到的字面量。想知道站上有哪些主题，看 `public/` 下有哪些 CSV。
- 解析逻辑切成两层：纯函数 `collectThemes(files)` 在 `src/` 里正常测；Vite 插件只负责列目录、读文本、调它一次、把跳过的原因打出来，薄到不测。测试不再断言"恰好有吃/玩/干三个主题"。
- CSV 文件同时是数据和配置。改名单的人现在有本事改坏首页入口的文案——但改坏的后果止于这一个主题被跳过，其余主题不受影响，与 0005 里"每个主题各自独立"的口径一致。
