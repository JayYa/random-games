# 主题由 `public/*.csv` 在构建期自动发现

主题就是 `public/` 下的一份 CSV：文件主名是 slug，文案写在文件头部的注释行里，构建期扫出来生成清单，编译进 bundle。原来加主题要写 CSV 再往源码的常量表里加一条，两处注定漂移，还让加主题变成了改代码。[ADR-0005](./0005-one-csv-per-theme.md) 否决运行时清单的理由（多一种失败方式）仍然成立，所以发现只发生在构建期，浏览器里不多一次请求、不多一种失败。

## Consequences

- **加一个主题 = 往 `public/` 扔一份带 `# entry:` 的 CSV**，不动代码、不改测试。想知道有哪些主题，看 `public/`。
- **文案是封闭的两个键**：`# entry:`（首页入口的说法，必填）和 `# title:`（玩法页标题，缺了退回 `entry`）。其余 `#` 行照旧当说明文字跳过。
- **slug 只接受 `[a-z0-9-]+`**：宁可跳过一份文件，也不要地址栏里出现百分号编码。
- **坏文件跳过，不拦构建**：数据文件是给非程序员改的，一份写坏的名单不该让整站发不出去。拦它的是测试：冒烟测试断言每份 CSV 都能解析成主题，`pnpm test` 跑在 `pnpm build` 之前。
- **CSV 同时是数据和配置**：改名单的人能改坏入口文案，但后果止于这一个主题被跳过。
