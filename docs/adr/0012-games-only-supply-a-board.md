# 玩法只交盘面，名单、开抽与结果卡片由玩法页宿主接

玩法记录只带一个盘面：盘面交出自己的 HTML 和结果卡片按钮上的字，挂上之后只管画和演，停下时报一声，被叫到时把名字写上或抹掉。建名单、名单写坏的错误页、结果卡片、开抽状态机、"开抽之后盘面锁死"的判据和拆卸，统一由一个与玩法无关的玩法页宿主接好。原来每个玩法拿到名单原文和最近中选、各自接一遍，两份接线已经走岔。

## Considered Options

- **玩法照旧是入口，在自己的挂载函数里先调宿主**：改动小，但"先调宿主、按什么顺序"仍由每个玩法各自记着，下一个玩法照样能漏写、写岔。
- **把开抽状态整个交给盘面**：盘面就能读到开抽阶段、绕开锁死判据。实际交给盘面的是一个开抽句柄，只有"开抽""盘面停下""锁没锁"三样。

## Consequences

- **盘面拿不到名单**：不知道候选有几个，也不知道最近中选，从接口上钉住 [ADR-0010](./0010-board-is-a-show-winner-drawn-after.md)。
- **停在哪一格仍是盘面自己的事**：宿主只叫盘面揭晓这个中选，不转手格子下标。
- **宿主是无头的**：写页面、建卡片都经注入的页面适配器，用例拿假页面和假盘面跑，不引入 DOM 测试环境。站内导航与宿主共用同一个页面适配器，宿主只看见与玩法页有关的那部分。
- **取名单、加载态和"取不到文件"归站内导航**：晚回来的名单作废是导航的规则。名单取回之后由导航造盘面、交上最近中选，调宿主。
- **加一个玩法 = 往玩法清单里加一条 slug 加盘面的记录**，不接任何会话。
