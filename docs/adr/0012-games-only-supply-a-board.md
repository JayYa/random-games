# 玩法只交盘面，名单、开抽与结果卡片由与玩法无关的地方接

玩法记录只带一个盘面：盘面交出自己的 HTML 和结果卡片按钮上的字，挂上之后只管画和演，停下时报一声，被叫到时把名字写上或抹掉。名单、名单错误、结果卡片、开抽状态机、"开抽之后盘面锁死"的判据和拆卸，统一由与玩法无关的地方接好：取名单、打开名单和四种名单错误归站内导航，开抽状态机和结果卡片归玩法页宿主。原来每个玩法拿到名单原文和最近中选、各自接一遍，两份接线已经走岔。

## Considered Options

- **玩法照旧是入口，在自己的挂载函数里先调宿主**：改动小，但"先调宿主、按什么顺序"仍由每个玩法各自记着，下一个玩法照样能漏写、写岔。
- **把开抽状态整个交给盘面**：盘面就能读到开抽阶段、绕开锁死判据。实际交给盘面的是一个开抽句柄，只有"开抽""盘面停下""锁没锁"三样。

## Consequences

- **盘面拿不到名单**：不知道候选有几个，也不知道最近中选，从接口上钉住 [ADR-0010](./0010-board-is-a-show-winner-drawn-after.md)。
- **停在哪一格仍是盘面自己的事**：宿主只叫盘面揭晓这个中选，不转手格子下标。
- **宿主是无头的**：写页面、建卡片都经注入的页面适配器，用例拿假页面和假盘面跑，不引入 DOM 测试环境。生产用同一个页面适配器同时满足站内导航与宿主；宿主只看见"写出玩法页"这一屏，选主题页、加载态和名单错误页在站内导航的页面适配器上。
- **取名单、打开名单和四种名单错误归站内导航**：取回名单原文后当场打开名单，"没取到"和读不懂、空、全部停用在这一处汇合，整个应用只有这里叫页面画名单错误。晚回来的结果作废是导航的规则，不论能开抽还是名单错误。能开抽时，导航造盘面，只把"抽一个中选"交给宿主。
- **宿主只收开抽状态机要的东西**：主题、抽中选、盘面、页面适配器和可选的计时器。它不知道名单原文、最近中选和随机源，什么时候抽中选（也就是什么时候记进最近中选）由它在盘面停下那一刻决定。
- **原意不变**：名单与名单错误仍由与玩法无关的地方接，盘面仍拿不到名单。名单错误从宿主挪到站内导航，只是把画错误页的地方收成一处。
- **加一个玩法 = 往玩法清单里加一条 slug 加盘面的记录**，不接任何会话。
