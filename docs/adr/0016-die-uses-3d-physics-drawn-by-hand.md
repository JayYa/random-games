# 骰子用 cannon-es 算 3D 物理，画面手写投影

骰子的抛必须真的决定哪一面朝上（[ADR-0006](./0006-pinball-slot-is-decided-by-physics.md) 那条原则）。正十二面体是一面一面翻倒、弹起、晃几下才停的，matter.js 只有 2D，模拟不出来，所以物理另用 cannon-es：一个凸多面体刚体、地面加四面墙，固定步长手动步进，停稳后法线最朝上的那一面就是朝上的面。画面不用 3D 库：盘面上只有一颗凸多面体，在 canvas 2D 上手写投影，背面剔除加平面着色就够，照旧经对齐画布（[ADR-0013](./0013-boards-share-only-fit-canvas.md)）。朝上的面只决定名字亮在哪儿，不决定谁中选（[ADR-0010](./0010-board-is-a-show-winner-drawn-after.md)）。

## Considered Options

- **2D 物理算滑行，按滚过的路程推算翻滚**：不加依赖，但看起来像一颗画了面的球在滚，停下前吸到最近的面还可能看得出一跳。
- **three.js 画面**：好看，有真阴影，但为一颗多面体拖进上百 KB；它自管像素比，绕开对齐画布；WebGL 对这点几何也不更快。
- **Rapier**：还在维护，还有跨平台确定的版本，但要下载 MB 级的 WASM。跨平台确定性用不上（[ADR-0008](./0008-matter-js-over-hand-rolled-physics.md) 只承诺同一运行环境内确定）。

## Consequences

- **cannon-es 自 2022 年起停更**，版本锁死。它是纯 JS、不碰平台，用到的接口又窄，停更的风险可控；物理收在骰子目录里，真要换库，改动只在一处。
- **先跑完模拟再回放**，同弹球机：`(抛的速度, 种子) → { 朝上的面, 轨迹 }` 是纯函数，进单元测试。斜靠在墙上、棱着地停住的，换种子在后台重跑，重试用尽就取法线最朝上的那一面；卡住的那一局永远不上屏。
- **靠分布冒烟测试兜底**：一批抛覆盖各种力度和方向，断言十二个面都至少朝上一次。面本就不追求等概率，不做卡方检验。
- **拖着抛和摇手机走同一个模型**：摇一下就是抛一次，水平加速度的方向和峰值折算成抛的速度。
- **键盘可达，与弹球机、求签筒不同**：骰子画布可聚焦、按按钮读出，Enter 或空格以随机方向和力度掷一次，收下后焦点回到画布。按键不声称能控制落点，不违反"用户能操作的东西必须真的算数"；弹球机和求签筒不可达，是因为它们的操作折不成一次按键。
- **摇手机的授权询问与求签筒共用**（[ADR-0015](./0015-fortune-sticks-rise-not-physics.md)）：同一套提示与入口，谁先问过就算整站问过，已被求签筒问过的不再问。盘面上不写操作说明，同弹球机。
- **帧循环学转盘**：只在滚、揭晓、抹掉和尺寸变化时画，静止时不跑 rAF。
- **cannon-es 单独成包、按需加载**，同弹球机加载 matter.js：盘面照旧同步造好，挂上时才加载物理；物理没到就抛，先压着，物理一到就出手。不玩骰子的人不下载它。
