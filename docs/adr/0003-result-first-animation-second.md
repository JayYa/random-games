# 先决定结果，再反算旋转角度

一次转动先用一次 `random()` 选出中选，再反算转盘需要旋转多少度才能让它停在顶部指针处（约 5~8 圈 + 3.5 秒 easeOutCubic）。替代方案是给转盘一个随机初速度、让它"物理地"停下来，结果由摩擦模拟决定。

选前者是因为随机性从此集中在一行代码里，其余全是确定性动画：结果可复现、可单元测试（选中项 → 目标角度的反算是这个项目唯一会算错且肉眼极难发现的地方），也可以向人解释清楚。代价是转盘的物理感是假的。

## Consequences

因此**不支持手指甩动来转**。甩动会暗示手势力度能影响结果，而结果在手指离开屏幕前就已经定好了，两者互相矛盾——只提供一个大按钮。另外落点取扇区内的随机位置而非正中，否则每次都停得过于整齐，反而显得像假的。

反算算错了肉眼看不出来，所以它得有一条用例守着，而不是靠注释在几个模块之间保持口径一致。这条不变量的说法是：**转盘停下之后，指针底下的扇区就是中选**。扇区与角度的换算（扇区占哪一段、指针底下是哪个扇区、画到画布上是哪一段弧）只有 `src/games/wheel/sectors.ts` 一处知道，会话、动画和画布三边都问它；再往下一层，「把任意角度折回一圈之内」不属于扇区而属于角度约定本身，扇区模块与动画的反算都要用，所以它和 `TAU` 一起住在 `src/angles.ts`，两边都向它要，不各写一遍。端到端那条用例在 `src/games/wheel/session.test.ts`，把中选一路过到最终角度，再问一次指针底下是谁。

这条 ADR 只管转盘。弹球机反过来——中选由球实际落进哪个落格仲裁，力度因此真的算数，见 [ADR-0006](./0006-pinball-is-arbitrated-by-physics.md)。
