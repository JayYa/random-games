# 盘面经各自的表面碰 DOM，用例挂生产盘面

盘面挂上之后碰 DOM 的一切都经本玩法的盘面表面：画一帧、要一帧、取消在等的帧、输入事件进来、按钮可不可按、尺寸变了、焦点交给谁、拆卸时解开监听。生产用由挂载点建出来的 DOM 表面，它只把调用转给画布、rAF 和 DOM 事件，连同作画代码一起不测；用例用假表面。原来写在挂载函数里的规矩——揭晓、抹掉之后要一帧，「转」受理了才起转，按钮跟着开抽句柄的锁走，尺寸变了要重画，拆卸时掐掉在等的帧——全部收进盘面本身。盘面工厂多一个可选参数，带表面工厂和随机源，默认是 DOM 表面和 `Math.random`，玩法清单不改。

用例经 `mountOnHost` 挂的就是生产盘面，只把表面和随机源换成替身；机器退为盘面的内部实现，不再单独当测试面。原来的机器用例各自造一个盘面、抄一份盘面 HTML、块名和收下按钮上的字，把机器当作挂上之后的盘面交回宿主，挂载函数里的规矩恰好落在没有用例的那一侧：少了揭晓之后那次重画，名字永远不会亮在转盘上，单元测试和 e2e 都发现不了。

本条补充 [ADR-0012](./0012-games-only-supply-a-board.md)（宿主无头、不引入 DOM 测试环境）与 [ADR-0013](./0013-boards-share-only-fit-canvas.md)（两块盘面只共用对齐画布），不推翻它们：表面按玩法各写一份，不共用类型，帧循环策略仍各归各。

## Considered Options

- **引入 happy-dom / jsdom，把挂载函数整段搬进用例**：与"碰 DOM 是系统边界、在边界上换替身"的约定相悖，canvas 在里面也画不出来，用例照样看不到画面。
- **只把帧请求注入机器**：补画和帧起停有了用例，可锁与按钮、焦点去向、尺寸重画、弹球机的指针捕获规则仍留在不测的挂载函数里。

## Consequences

- **作画只有一条路径**：画面一变就向表面要一帧，每一帧里推进时间、交出画面、交给表面画；已经有一帧在等时不再多要。没有"同步补画"和"帧循环"两条路要分别想清楚。
- **用例断言画出来的画面**：最后画了什么、有没有帧在等、按钮可不可按，加上宿主上的结果卡片，不断言机器的内部状态。
- **盘面的 HTML、块名和收下按钮上的字只在盘面里写一份**，DOM 表面靠盘面写进页面的那份 HTML 找元素。
- **揭晓晚画一帧**：揭晓之后要一帧，不当场画。离弹结果卡片还有约 0.8 秒（[ADR-0010](./0010-board-is-a-show-winner-drawn-after.md)），晚一帧看不出来。
- **不测的只剩 DOM 表面与作画代码**，由 e2e 冒烟测试和浏览器核验兜着。加第三个玩法时照同一形状写：规矩进盘面，DOM 进表面。
