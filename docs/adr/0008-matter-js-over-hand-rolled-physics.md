# 用 matter.js，放弃跨环境的确定性

弹球机的物理用 matter.js，脱开它自带的 Render 只用 Engine，固定步长手动步进。这是这个仓库的第一个运行时依赖。

手写也完全可行——一个动圆对一堆静止圆和线段是刚体物理里最简单的一档，两三百行能写完，而且能把浮点行为完全攥在手里。选库是因为弹球机不会是最后一个玩法：选型该按"下一个玩法好不好写"来判断，而不是按这一个玩法的最小需求。matter.js 在这一点上最省心，API 也最平易。

## Consequences

- **确定性降级**：matter.js 的浮点结果不保证跨浏览器、跨机器一致，因此 [ADR-0006](./0006-pinball-is-arbitrated-by-physics.md) 的确定性只承诺"同一运行环境内，同样输入必得同样落格"，不承诺"这条链接在任何机器上都打进同一格"。这对单元测试够用（CI 是固定环境），对这个站的产品目标也够用（没有人需要复现别人的那一发）。
- **必须关掉 sleeping、绕开引擎自己的时间步**，否则同样输入不再必得同样结果。
- **盘面的物理参数**（重力、恢复系数、钉阵间距、风车角速度、隔板高度）集中在一处常量表里，调参不用翻代码。
- **靠分布冒烟测试兜底**：跑两百发覆盖全部力度区间，断言 8 个落格每格至少中一次。钉阵摆得让某一格永远打不中，肉眼极难发现——这正是 ADR-0003 说的那类"会算错且看不出来"的地方。不做卡方之类的统计检验：ADR-0006 已明确这个玩法不追求等概率，检验没有该过的基线。
