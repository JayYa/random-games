# 两个盘面只共用对齐画布，帧循环各归各

转盘和弹球机作画前都经对齐画布拿上下文：把像素缓冲对齐到封顶后的设备像素比，交回按 CSS 像素设好变换的上下文。共用的只有这一步，帧循环、尺寸观察与拆卸各归各的盘面。两边帧循环策略正好相反：转盘静止时不跑 rAF，只在转、揭晓、抹掉和尺寸变化时画；弹球机的风车一直在转，rAF 常转。对齐像素缓冲的几条规则则两边完全一样，又属于写错了肉眼看不出的那类，值得只有一处实现。

## Considered Options

- **共用帧循环加尺寸观察的画布驱动**：只能靠一个"要不要常转"的开关分叉，差异挪进参数，驱动本身是浅的，改一边还可能波及另一边。
- **接收机器与作画函数的整个盘面外壳**：揭晓、复位、焦点和输入绑定都得穿过它，接口比两个盘面的渲染层加起来还宽。

## Consequences

- **像素缓冲的规则只有一处**：两块画布不会一块封顶一块不封，也不会在奇数像素比下差一像素。
- **弹球机没有尺寸观察不是缺陷**：rAF 常转，下一帧自然画对。转盘静止时不要帧，所以它自己观察尺寸与像素比。
- **什么时候重新打开**：出现第三个玩法，且它的帧循环与现有某一方同形时，再看要不要把那种帧循环收成共用。
