# 求签筒用冒头模型，不用物理

求签筒的操作是甩，甩得越猛签冒得越快，这一点必须真的算数（[ADR-0006](./0006-pinball-slot-is-decided-by-physics.md) 那条原则：用户能操作的东西必须真的算数）。但我们没有用 matter.js 去模拟一把签在筒里互相挤，而是只算打头那根签的冒头：每一下甩按速度往上加，停手片刻就回落，涨到顶签就掉出来。签又细又长、挤成一把，在 2D 物理里既不稳定也难调；而且签都长一个样，哪根被挤出来对使用者毫无意义，真正该算数的只有出签快慢。哪根签打头随机定：第一下甩时定一根，冒头往回滑之后再甩就换一根，且不与上一根相同（上一次开抽掉出来的也算），都与谁中选无关（[ADR-0010](./0010-board-is-a-show-winner-drawn-after.md)）。

## Considered Options

- **matter.js 模拟整把签**：最"真"，也顺着 [ADR-0008](./0008-matter-js-over-hand-rolled-physics.md) 选库时"下一个玩法好写"的初衷；但细长刚体堆叠容易抖、穿模，调参成本远高于收益。
- **点一下就自动摇**（同转盘）：最省事，但甩是求签筒唯一的乐趣，不能是假的。

## Consequences

- **冒头是确定性的纯函数**：`(甩的速度序列, 时间, 随机源) → 冒头`，进单元测试，不依赖物理引擎，也没有跨环境浮点的问题。
- **只要一直在甩就一定出签**：在甩的时候冒头不回落，回落只在停手之后发生，轻轻晃的人也不会永远出不了签。代价是停得久了、冒头开始往回滑，再甩就换一根签打头，之前冒的高度跟着旧签滑回筒里，这是为了让使用者看得出换了一根签。
- **开抽从签掉出筒口算起**：之前的甩都是热身，可以随时停、随时离开；这跟弹球机"松手发射才算"同理。
- **键盘不可达**：甩是拖拽或摇手机，暂不提供键盘等价操作，跟弹球机一样是明知的代价。
- **摇手机按平台区别对待**：Android 直接读运动传感器；iOS 必须在使用者点按的那一刻请求授权，所以第一次进求签筒时先给一个站内提示，点了才弹系统授权框，这台浏览器只问一次，签筒下方常驻一个重新开启的入口。摇手机与拖着甩走同一个冒头模型，低于门槛的加速度不算，免得拿着手机走路时签自己冒出来。
