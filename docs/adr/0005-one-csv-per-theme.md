# 一个主题恰好一份 CSV，用 hash 地址

每个主题各有一份独立的 CSV，互不牵连（主题如何被发现见 [ADR-0009](./0009-themes-are-discovered-from-csv-files.md)）。站点用 hash 地址：首页是选主题页，认不出的地址回落到首页。

## Considered Options

- **一个 CSV 加一列 `theme`**：名单从"一个文件"变成"一个文件的切片"，解析错误报的行号对不上使用者心里的那份名单；一个主题写坏一行还会连累其余主题。
- **主题清单做成运行时读取的 `public/themes.json`**：给站点添一种新的失败方式——清单取不到或写坏了，首页连按钮都出不来。
- **history 地址（`/random-games/play`）**：GitHub Pages 项目子路径下刷新会 404。
- **不做地址，点主题直接换 DOM**：刷新回首页、后退键直接出站、链接没法分享。

## Consequences

- **错误提示一律用中性的"候选"，不随主题变**：错误页的读者是去改 CSV 的人。
- **每一页都带回首页的入口**：分享出去的链接直接落在玩法页上，得让人知道还有别的主题；名单写坏的主题也不能是死路。
- **首页不读任何名单**，只取当前主题那一份。坏名单要点进去才发现，换来每个主题的"取名单 → 解析 → 盘面或错误页"各自独立。
- **站点不记住上次选的主题**：直达某个主题靠书签，不靠程序替人记。
